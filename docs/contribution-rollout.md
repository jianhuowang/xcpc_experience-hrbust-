# 投稿整理与周四试用

日期：2026-09-14。当前修复独立基于 main，不依赖尚未合并的 PDF 修订 PR。具体收录标准以 [Schema](../.agents/skills/xcpc-experience-coach/references/contribution-schema.md) 为准。

## 这次解决什么

原 MCP 只索引协会条目和外部清单，Schema 不在其中，服务说明又写“不投稿”。网页模型因此找不到契约，并猜出了 `type: experience`、`status: draft` 等不匹配字段。

新增无参数的只读 `contribution_guide`，返回固定白名单中的 Schema、Skill 和 PR 模板，附与知识库一致的 Git revision 和固定链接。Schema 内补完整起草骨架及收录门槛；工具不创建文件、验证草稿或提交 PR。保留原来的 H1/H2 正文限制，投稿指南不包含题解。正在盲做时，不能借投稿查重为由升级读取权限。

采用已有协议与校验器，不增设 RAG、账号系统或写入服务。把 Schema 塞进普通经验索引会混淆治理文档与协会知识；复制一份 MCP 专用 Schema 会产生两套规则，因此直接读取同一提交中的原文件。

## 收录判断示例

| 材料 | 处理方向 |
|---|---|
| “今天做出一道构造题，很有成就感，发现要大胆猜” | 个人复盘；还没有别人可以执行和验证的结论 |
| “极大化合法集合：先排除非法位置，把其余位置全部选上” | 仅凭这句话不足投稿：两个位置单独合法，不保证同时选择合法；需明确约束是否独立、证明整体合法及目标为何适合取全部 |
| 一道题中识别了集合封闭性、证明可同时选择，并记录不成立的条件和验证 | 可作为单次经验起草；先检查旧库是否已有同结论 |
| 已有 `__int128` 经验换题号、标题再次提交 | 引用原条目，不新建 |
| 同一 `__int128` 结论补充真实的新环境测试 | 更新原条目的证据或边界，保留稳定 ID |

不按题目难度或篇数衡量贡献。不是“所有做题记录都进公共库”，也不是“必须原创算法才能投稿”。一条能让下一位成员少踩坑的具体结论，比堆砌术语的长篇总结更有价值。

## 自动创建 PR 的取舍

以下为针对本项目的工程估计，不是平台承诺：

| 方案 | 实现/维护难度 | 当前建议 |
|---|---|---|
| 读取规则，AI 起草，成员手动 PR | 低；复用现有 MCP 和 CI | 本次采用 |
| 在成员自己的开发 Agent 中用 GitHub 凭证提交 | 中低；仍需成员登录、核对 diff、明确授权 | 已熟悉开发工具的成员可选，不影响网页入口 |
| 公网 MCP 代多人自动写分支和创建 PR | 中高；API 调用简单，可靠授权及错误处理是主要工作 | 观察真实投稿频率和手工卡点后再决定 |

GitHub 提供[写文件接口](https://docs.github.com/en/rest/repos/contents#create-or-update-file-contents)与[创建 PR 接口](https://docs.github.com/en/rest/pulls/pulls#create-a-pull-request)，分别涉及 Contents 和 Pull requests 写权限。ChatGPT [Developer mode](https://developers.openai.com/api/docs/guides/developer-mode)支持读写 MCP 工具、OAuth 与写操作确认，因此技术上可行。

若以后建设公网写入，至少需要用户身份/授权、限制目标仓库和知识目录、禁止写 main、展示确定 diff 后确认、实际校验、基于原文件 SHA 防覆盖、重复请求防重以及失败重试/审计。不能给当前无鉴权公开端点直接挂维护者写令牌。审核合并仍由维护者执行。这些是未来写服务的必要边界，不是本次只读工具的新审批流程。

## 周四推广前

1. 合并本修复并确认 Render 部署到对应 main revision；刷新 ChatGPT 应用工具，新聊天应发现 `contribution_guide`。本地协议测试不能替代此步骤。
2. 用三种短材料验收：可投稿的真实经验、纯感想、同结论重复；再验证一次证据缺失时会追问。应先读 Schema，不能猜字段或伪造验证。
3. 一位成员走完“给材料 → 草稿/补丁 → 手动 PR → CI → 维护者审核”的完整流程。只做草稿展示时不声称草稿已校验。
4. 指定实际接收 PR 的维护者，并公开说明外部讲义仍可能有转录缺失、AI 草稿需要复核。先以小范围试用收集查询和投稿卡点，不以增加条目数为目标。

上述线上验收与成员流程尚需实际执行，不能仅因自动化测试通过就宣布已经完成。
