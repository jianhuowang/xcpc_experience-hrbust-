# 投稿初稿审阅流程实施计划

目标：网页 MCP 与本地 Skill 都先交付正文尽量完整的初稿，集中待确认项；用户确认后输出便于复制的最终文件与 PR 信息。

架构：复用 contribution_guide 返回的共享 Schema，Skill 与 MCP 提示只负责引导。沿用现有 Markdown 校验器，无新工具、字段或依赖。

## 约束

- 新条目使用 short-title.md，旧 ID、作者及历史证据保持不变；更新优先最小补丁。
- 未知 authors、updated 等元数据留空，来源和验证无材料时保留空章节，缺项说明集中在稿件外。真实性、适用条件与未验证限定属于知识内容，不能为稿件干净而删除。
- 初稿一般 500～1000 字（不含代码、公式、来源），允许更短或更长，不增加 CI 字数限制，各节避免重复。
- 正文认可不是发布授权；不自动创建、推送或合并 PR。未执行的检查不勾选通过。
- 最终 Markdown 用单个四反引号代码块，内部三反引号代码块保留；Frontmatter 逐行，公式仅一份源码。提醒放在代码块外，未知项仍须补齐后才能通过校验。

本地结果：49/49 测试通过、5 条知识校验通过、Skill 结构校验通过。下面的实际 Agent 对话验收尚未执行。

## 行为验收用例

1. 初稿：模拟 Trie/LCP 材料，说明最终 cnt 分桶、后缀最大值，未提供作者、日期与真实来源，请先给初稿。预期：主题文件名、完整章节、空字段/空来源、稿外集中疑问与模拟提醒；不编造 AC 事实，不提前发布。
2. 审阅后：“正文可以，输出最终稿，未知信息仍由我填写；不发布。”预期：单一可复制源码块和独立 PR 标题/描述；必填项仍空则稿外提醒补齐，未运行的校验保持未勾选；无外部写操作。
3. 更新旧条目：补充真实环境自述，要求先看修改。预期：保留旧 ID、原作者和已有证据，只展示必要改动，未核实因果保持限定。
4. 简单经验不足 500 字或复杂经验超过 1000 字：不为字数补废话或丢条件；CI 无字数拦截。

网页实际输出需新版本部署并刷新连接器后执行；用户级 Skill 需更新副本后再用相同材料验收。
