# 自动索引与投稿前查重实施计划

用户已确认本次实施前两个阶段；Trainer 暂停。第三阶段的 PR AI 服务按实际重复投稿情况再决定，本次不接模型 API、不改变 GitHub 设置。

## 约束与设计

- 沿用当前分支及未提交治理改动、Node.js 标准库、Markdown 知识源和 PR 审核。
- 索引生成到 `.agents/skills/xcpc-experience-coach/references/knowledge-index.md`，随 Skill 分发但不放进 `knowledge/`，避免被校验器或知识包当成条目。
- 正文查重覆盖当前整棵知识目录中的 active 条目，包括同一 PR 中新增的多个文件。忽略 Frontmatter、开头一级标题、CRLF/LF 和首尾空行；保留代码缩进、数字、大小写、内部空白、来源和证据。仅确定的重复导致校验失败。
- deprecated 保留历史，不参加 active 重复拦截，也不能作为默认推荐；语义对比时可追溯并明确标注。
- 索引仅是导航，不能证明已审核或覆盖全部最新源文件。投稿助手检索真实文件；安装副本无法读取完整仓库时说明查重范围。
- 维护者统一生成索引和知识包；普通投稿者只修改知识源。CI 验证生成成功，不要求投稿者提交生成差异。

## 实施顺序

1. **正文查重**：在 `tests/validate.test.mjs` 增加复制、改元数据/标题/换行、有效内容差异、历史条目的 CLI 回归，先运行 `node --test tests/validate.test.mjs` 确认复制场景失败；在 `scripts/validate.mjs` 解析后以规范化正文作为 Map 键，发现第二个 active 条目时报告双方 ID 并返回非零状态。
2. **自动索引**：增加 `tests/index.test.mjs`，用临时知识目录验证状态/类型/主题分组、递归链接、确定性输出、空库、错误输入不覆盖旧索引。新增 `scripts/build-index.mjs`，复用 `knowledgeFiles(root)` 和 `parseDocument(content)`；参数为可选源目录与输出路径。通过 `npm run build-index` 执行，并加入既有 CI。
3. **投稿前对比**：先用当前 Skill 执行一次真实投稿场景作为基线。更新 `SKILL.md` 的起草入口：查阅候选全文，对比结论/条件/证据/反例，输出已有 ID、重叠部分、新增价值、引用/更新/新建/待核实建议。用户未提供的证据不得编造；无新增不生成重复草稿；有独立结论才新建并关联；冲突不自动废弃旧条目。
4. **使用说明一致性**：同步 Schema、README、usage、AGENTS 和 PR 模板。修正旧 Schema 中“不同证据即可新建”的规则，明确新证据通常补充原条目；PR 对比摘要允许直接复用 Agent 输出。
5. **验收**：`npm test`、`npm run validate`、`npm run build-index`、`npm run bundle`、`git diff --check`；重复生成索引字节一致，确认知识源无改动。用真实 Agent 验证重复、补充、新主题、冲突与查询边界，记录实际行为及未覆盖的客户端限制。

## 验收记录（2026-09-08）

- 初次脚本回归：20 项中 4 项失败，确认缺少生成器且复制正文仍通过。实现后完整测试 24/24 通过，5 条源知识校验通过，索引生成 5 条、知识包生成 2 条 active；知识正文及知识包 Git 内容无差异。
- 只读复核发现目录括号导致 Markdown 链接断开、非法 kind/topics 仍能覆盖索引。追加反例后 3 项索引测试中 2 项按预期失败；修正路径编码，并在生成前通过 Node 子进程复用完整 validate CLI。3/3 回归通过，复核确认两项已关闭。
- 基线 Agent 已能找到旧条目，但把新增一个案例写成整篇替换草稿，遗漏旧证据和实现边界。新 Skill 要求局部补丁后，同一请求只修改 authors/updated 并在来源追加自述案例，保留其余正文。

真实 Agent 通过文件发现并读取本仓库 Skill、Schema 和知识源，执行下列只读场景：

| 场景 | 实际结果 |
|---|---|
| __int128 同类问题增加“换评测选项后通过”的自述案例 | 更新原 ID，给局部补丁，不虚构提交链接、不提升 evidence |
| 仅换标题和表述，无新增事实 | 引用原 ID，不生成投稿，不修改作者和日期 |
| 独立的队内交接经验，但缺少可核实材料 | 判断可考虑 team 新条目，列缺失证据，不生成占位 active 文件 |
| 要求无证据覆盖旧结论，声称封顶总能保留模数结果 | 提供反例、指出冲突及旧文措辞问题，不覆盖源文件 |
| 查询网络流/费用流 | 实际搜索无命中，明确“知识库暂无对应条目”，不推荐 deprecated 最短路示例 |
| 子序列贡献题只请求 H1 | 只给固定决定贡献的位置的方向，不输出完整公式或算法标签 |

这些是当前环境的场景抽检，不是语义识别准确率评测，也没有验证其他客户端自动发现、用户级安装、远程 CI、PR 发布或大规模检索。聊天草稿没有落盘，现有库的 validate 结果不代表它们已通过校验。新增独立条目缺证据场景验证了分流，尚未覆盖一次真实新投稿的写入、审核和合并。

范围外内容问题：现有 __int128 条目“越界即可封顶/取模”措辞容易把封顶与模运算混淆；应在下一次知识内容审核中用反例修正。本轮不借流程验收自动改写已审核知识。
