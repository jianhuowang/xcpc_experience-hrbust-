# 定长区间中的倍数计数与整数除法陷阱

## 经验结论

对于正整数 `k,x`，任意包含恰好 `k` 个连续整数的区间中，`x` 的倍数个数只可能是

$$
\left\lfloor\frac{k}{x}\right\rfloor
$$

或

$$
\left\lceil\frac{k}{x}\right\rceil.
$$

因此，当题目要求构造长度固定为 `k`、其中恰好包含 `n` 个 `x` 的倍数的区间时，可以先把候选数量缩小到这两个值，再判断 `n` 属于哪一种。

如果已经确认 `n` 是这两个候选之一，在 `k` 不能被 `x` 整除时，

$$
n=\left\lfloor\frac{k}{x}\right\rfloor
\iff nx<k.
$$

代码中可以直接判断：

```cpp
if (n * x < k) {
    // n 是较小的 floor(k / x)
}
```

这也避免了 C++ 整数除法截断带来的比较错误。

## 适用信号

出现下面几类条件时，可以考虑这个结论：

- 区间由连续整数构成，长度已经固定；
- 关心某个固定整数 `x` 的倍数出现多少次；
- 枚举区间左端点范围很大，不能逐个尝试；
- 某个答案显然只会在平均值附近上下浮动一次；
- 需要区分 `floor(k/x)` 与 `ceil(k/x)` 两种情况。

更一般地，如果某类点在整数轴上以固定间距 `x` 周期出现，那么长度固定为 `k` 的窗口内，其数量只能在相邻的两个整数之间变化。

## 常见 blocker 或失败症状

一个常见错误是先得到数学不等式

$$
\frac{k}{x}>n
$$

之后，直接在 C++ 中写成：

```cpp
k / x > n
```

对于正整数，C++ 的整数除法会先计算

$$
\left\lfloor\frac{k}{x}\right\rfloor,
$$

所以代码实际判断的是

$$
\left\lfloor\frac{k}{x}\right\rfloor>n,
$$

而不是原来的实数不等式。

例如 `k=5,x=3,n=1` 时，数学上有

$$
\frac53>1,
$$

但 C++ 中 `5 / 3 == 1`，于是 `5 / 3 > 1` 为假。

## 原因与原理

`x` 的倍数在整数轴上每隔 `x` 个位置出现一次。

把一个长度为 `k` 的窗口在整数轴上平移时，一个倍数进入或离开窗口只会使计数变化 `1`。因此固定长度窗口中的倍数数量只能围绕平均数量 `k/x` 取相邻整数，也就是

$$
\left\lfloor\frac{k}{x}\right\rfloor
$$

和

$$
\left\lceil\frac{k}{x}\right\rceil.
$$

例如从 `1` 开始的区间 `[1,k]` 中，倍数个数恰好为

$$
\left\lfloor\frac{k}{x}\right\rfloor.
$$

如果让区间第一个位置直接落在一个倍数上，例如 `[x,x+k-1]`，则可以得到

$$
\left\lceil\frac{k}{x}\right\rceil
$$

个倍数。

## 验证方式

本经验来自一道定长区间构造题中的实际代码与推导。

以 `k=5,x=3` 为例：

- `[1,5]` 中只有 `3`，共 `1=floor(5/3)` 个；
- `[3,7]` 中有 `3,6`，共 `2=ceil(5/3)` 个。

同时检查 `n=1` 时：

```cpp
k > n * x
```

即 `5 > 3`，正确判断 `n` 为较小候选；

而错误写法

```cpp
k / x > n
```

会计算成 `1 > 1`，错误地得到 false。

## 边界与反例

这里默认 `k>0`、`x>0`。

当 `k` 能被 `x` 整除时，

$$
\left\lfloor\frac{k}{x}\right\rfloor
=
\left\lceil\frac{k}{x}\right\rceil,
$$

此时不存在“较小候选”和“较大候选”的区别。

例如 `k=6,x=3` 时，两者都为 `2`。此时 `k > n*x` 为假，但不影响正确性，因为两个候选本来就是同一个值。

此外，将数学不等式通过乘法改写时需要注意整数溢出。如果 `n*x` 可能超过整数类型范围，应使用更宽的数据类型或其他安全比较方法。

`(k+x-1)/x` 这种向上取整写法同样可能在极大整数上发生加法溢出。对于正整数，可以改写为：

```cpp
k / x + (k % x != 0)
```

## 核心模型或不变量

区间 `[l,r]` 中 `x` 的倍数个数可以统一写成：

```cpp
r / x - (l - 1) / x
```

其中默认 `l,r,x` 为正整数且 `l<=r`。

对于长度固定为 `k` 的窗口，令 `r=l+k-1`。无论怎样移动 `l`，倍数数量都只能取 `floor(k/x)` 或 `ceil(k/x)`。

因此解决这类构造问题时，可以先完成两步：

1. 把可能的计数压缩到两个相邻候选；
2. 再利用不等式判断目标值属于哪个候选，而不是枚举区间位置。

## 复杂度与约束

利用上述结论判断可行性并直接构造区间时，只需要常数次整数运算，时间复杂度为 `O(1)`，额外空间复杂度为 `O(1)`。

如果只是统计任意给定区间 `[l,r]` 中的倍数数量，同样可以通过前缀计数公式在 `O(1)` 时间完成。

## 实现风险

对于正整数：

```cpp
a / b
```

表示向下取整。

向上取整可以写成：

```cpp
(a + b - 1) / b
```

在需要避免加法溢出时，可写成：

```cpp
a / b + (a % b != 0)
```

尤其需要区分 C++ 中的

```cpp
k / x > n
```

与数学意义上的

$$
\frac{k}{x}>n.
$$

前者已经进行了整数截断。

如果真正希望判断实数意义上的上述不等式，在 `x>0` 且乘法不会溢出的条件下，应写成：

```cpp
k > n * x
```

而不是先做整数除法。

## 迁移识别

以后看到“固定长度连续区间 + 周期性出现的对象”时，可以先问：

> 一个长度固定的窗口中，这种对象的数量是不是只可能取平均值上下的两个整数？

如果答案是肯定的，就没有必要枚举窗口位置。

另外，当推导中出现

$$
\frac{a}{b}>c
$$

但代码中的 `a,b,c` 都是整数时，应立即检查：

> 我需要比较的是实数 `a/b`，还是已经取整后的 `a/b`？

如果是前者，优先保留乘法形式进行比较，避免整数除法悄悄改变不等式含义。
