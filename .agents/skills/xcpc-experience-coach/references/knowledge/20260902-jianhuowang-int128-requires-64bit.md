# 用 __int128 前先确认评测环境是 64 位

## 经验结论
"评测机不认 `__int128`"往往是一种误判。真正原因通常是提交时选的语言环境是 **32 位 GCC**（如 `C++17 (GCC 7-32)`），而不是语言标准版本太旧。`__int128` 是 GCC 的扩展，只在**目标支持 128 位整型**时可用；在 32 位 x86 目标（i386/i686）下 GCC 不提供 `__int128`，因此使用它会编译失败或行为不可预期。本机用 64 位 MinGW 能编过、能跑对，于是产生"我电脑上没问题"的假象。

结论：**写 `__int128` 前先确认目标编译器是 64 位**；更稳妥的是不依赖 `__int128`，直接用溢出安全的写法：

```cpp
if (sum > CAP / times)
    sum = CAP;
else
    sum *= times;
```

## 适用信号
- 本地（64 位 MinGW / clang）编译通过，提交到某个语言版本/环境却编译失败或行为异常。
- 评测环境名里出现 `32`、`32-bit`、`GCC 7-32` 等字样，或语言列表存在 32 位选项。
- 涉及可能超出 `long long` 表示范围的大整数乘法/加法，正在考虑用 `__int128` 或需要自行做溢出保护。

## 常见 blocker 或失败症状
- 在 32 位 GCC 环境下使用 `__int128`：编译期报不支持/未定义，或目标不提供 128 位整型。
- 本地 64 位环境正常，产生"本地对、评测错"的偏差。
- 被误导去排查语言标准新特性兼容性，方向错误，浪费时间。

## 原因与原理
`__int128` 是 GCC 扩展，不是 C++17 标准内建类型；GCC 仅在目标支持 128 位整型运算时启用它。对 x86 而言，通常要求 64 位目标（x86-64 / x32），32 位目标（i386 / i686）不在支持之列。因此"是否支持 `__int128`"取决于**目标架构/位数**，而非语言标准版本；GCC 7 本身支持 `__int128`，只是 32 位目标不提供。

溢出安全写法把检查前移，用**除法放缩**判断乘法是否会越界：`times > 0` 时，`sum * times <= CAP` 等价于 `sum <= CAP / times`。先判断 `sum > CAP / times` 再决定是否封顶，使中间结果和最终结果都不越界，且不依赖 `__int128`。

## 验证方式
- 分别用 64 位与 32 位目标编译同一段用到 `__int128` 的代码：确认前者通过、后者报错或不支持。
- 构造覆盖边界的样例（如 `sum * times` 恰好接近/超过 `long long` 上限），对比 `__int128` 版与溢出安全版结果一致。
- 对拍：以不越界的朴素 `long long` 参考实现核对溢出保护分支，确认封顶逻辑正确。

## 边界与反例
- 若评测环境确为 64 位（如 `GNU G++17 64-bit`、`GNU G++20/23 64-bit`），`__int128` 可用，无需改写成溢出保护写法。
- `__int128` 不能直接用 `cin/cout` 或 `printf` 输出，需手动拆分高低位，本身有实现成本。
- 溢出保护写法只适用于"越界即可封顶/取模"或能用 `CAP` 表示上限的场景；若需精确大整数结果，应改用大数或 `__int128`，不能简单封顶。

## 来源
- GCC 官方文档 128-bit Integers：https://gcc.gnu.org/onlinedocs/gcc/_005f_005fint128.html
- 个人提交复现：本地 64 位 MinGW 通过，选择 `C++17 (GCC 7-32)` 环境时失败。

## 核心模型或不变量
核心不变量：任何被乘/被加后可能超过 `long long` 表示范围的操作，都必须在**发生溢出之前**完成判断与兜底。乘法安全不变量为：`times > 0` 时，`sum * times <= CAP` 等价于 `sum <= CAP / times`，因此先判断再封顶可保证中间值与最终值均不越界。

## 复杂度与约束
- 溢出保护：每次仅一次整数除法加一次乘法，O(1)，无额外空间。
- 约束：`sum`、`times`、`CAP` 使用 `long long`；`times > 0`；`CAP` 为可接受上限。若 `times` 可能为 0 或负，需单独处理判断分支。

## 实现风险
- 本地 64 位与评测 32 位不一致：用 `__int128` 时，务必在提交环境的真实目标上验证，不能只看本地通过。
- `__int128` 的输入/输出（`cin/cout`、`printf`）需自行实现，容易引入新 bug。
- 除法放缩 `CAP / times` 在 `times == 0` 时除零，需先判零。
- 若 `CAP` 或中间值与题目约束不一致，封顶逻辑会改变结果正确性。

## 迁移识别
- 看到评测机语言环境名带 `32` 或较老的 GCC 版本，先在本地用同样目标编译一次 `__int128` 用例。
- 大整数运算可能溢出时，优先采用"先判断再运算"的溢出安全写法，而不是依赖 `__int128`。
- 凡本地与评测不一致的编译/运行差异，先怀疑**环境位数/目标架构**差异，而不是语言标准新特性。
